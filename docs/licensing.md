# 授权与主账号管理

当前有独立授权服务及主账号管理网页源码；本轮没有部署真实授权域名，没有签发客户账号，不代表商业发行已通过。

## 主账号管理端

运营者部署现有授权服务后，在真实域名的 `/admin` 使用部署时设置的管理员密码登录。无默认账号或密码，不另建登录系统。管理员会话仅驻留当前页面内存，刷新需重新登录，退出撤销会话。

现有能力包括：

- 开通客户授权，选择功能及 **3 / 30 / 180 / 365 天**周期，首次激活才起算。
- 查看授权编号、客户、设备、激活/到期/停用状态。
- 续期、停用、恢复、正常换机或管理员迁移/释放设备。
- 查看操作记录。

本轮补齐已开通账号的“调整开放功能”：保留原到期时间和停用状态，增加授权版本、撤销旧刷新凭证。客户重新登录后取得新功能；显式空集合不开放任何新工作功能。未知功能会被拒绝。

新增管理 API：`POST /admin/licenses/{license_id}/features`，body 为 `{"features":["workspace.use","script.generate"]}`。复用已有管理员 Bearer，不接受额外字段，不向浏览器返回密码哈希或刷新凭证。

## 客户使用与边界

客户在桌面“设置 → 软件授权”输入编号和密码；密码不保存。系统密钥库保存设备、刷新凭证、时间及撤销状态；签名租约最长24小时，且不超过套餐到期时间。客户端只包含Ed25519公钥。已开放功能来自已验证的签名租约，并在设置中显示。

联网每60秒验证，停用、功能变更和换机在服务器立即限制后续刷新；已离线设备可能继续使用尚未过期的租约，最长24小时。这是离线能力的实际限制，不能声称所有设备立即停用。恢复不延长到期时间，客户需重新登录。续期不自动恢复停用账号。

正常换机先在旧设备释放，再到新设备登录；旧设备不可用时，由管理员使用新设备编号迁移或释放。设备迁移不转移本地资料，资料需要用户自行合法备份/导入。

到期/停用不删除资料，仍允许本地阅读与保全导出；供应商数据的留存和导出规则仍独立生效。账号身份与工作区归属规则沿用既有实现，不用换号绕过原资料归属。

## 正式配置与启动前拒绝

`deploy/license/production.env.example` 是公开配置模板，必须填入同一个真实 HTTPS 根域名；不能用占位值、本机地址、测试域名或带凭证URL。运营者自行准备 PostgreSQL连接、Ed25519签名私钥、管理员scrypt密码哈希和真实域名证书。

现有 `license_service.application` 生产入口在连接数据库前验证：

1. `LICENSE_PUBLIC_URL` 为真实域名 HTTPS 根地址，`LICENSE_PUBLIC_HOST` 一致。
2. `LICENSE_TLS_CERT_FILE` 指向可解析、当前有效、SAN覆盖该域名的非自签名叶证书。
3. PostgreSQL DSN、Ed25519签名私钥和管理员哈希格式有效。

缺项、占位、证书过期/不匹配会拒绝启动。反向代理模板只接受配置域名，TLS私钥只挂载给nginx；授权服务只读取公开证书。配置检查不证明DNS所有权、公有CA信任链、线上TLS或可用性，真实公网部署验收仍待完成。

桌面商业包使用 `commercial-license.template.json` 填写真实服务URL和签名公钥，并与 `commercial-release.json` 强制标记一同打包。标记存在但授权配置缺失时拒绝启动；内部包明确显示未验证商业授权，不得改称正式商业包。

秘密位于运营者主机 `deploy/license/secrets/`，受本目录 `.gitignore` 排除，不提交、不进入桌面包。公开配置模板不含真实密钥或客户账号。更完整的既有协议和离线边界见 [commercial-license.md](commercial-license.md)。
