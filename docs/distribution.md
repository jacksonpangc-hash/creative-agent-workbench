# 发行状态与交付说明

本轮源码、内部安装包、浏览器扩展包、真实商业集成和公开发行分开记录。只有最终交付记录支持的构建/设备结果才可标为通过；代码存在或模板可填写不是上线证据。

## 内部版与正式版

内部版用于本地受控体验，界面显示“内部开发模式，未验证商业授权”。模型和外部商业数据仍由使用者自行连接并付费，缺少连接、数据或媒体时显示真实缺口，不用示例数据充当已接通服务。

正式版除实际桌面可运行外，仍需运营者提供：

- 真实授权域名、TLS证书、PostgreSQL、Ed25519签名私钥和管理员密码哈希；实际备份恢复与运行验证。
- 仅含对应公钥/真实HTTPS地址的强制商业授权配置及发行标记。
- 正式macOS签名/公证、Windows签名与安装/更新/卸载实机验证。
- Chrome及Edge独立商店账号、ID、URL、审核结果和公开隐私政策。
- 现有源码、FFmpeg及其他第三方依赖的许可证、对应源代码与分发权利核对。

这些外部条件没有完成前，不得称为“已公开商用上线”或“已通过平台审核”。AGPL及第三方授权不会因增加账号收费模块而自动改变。

## 浏览器交付

`browser-extension/package.py` 将生成Chrome提交ZIP、Edge提交ZIP及固定ID内部开发ZIP/解压目录，图标与审核文案在 `browser-extension/store-materials/`。正式URL缺失时设置显示“商店版待上架”。开发ID不能替代两店正式ID。

本机桥是同一Rust工程中的 `creative-browser-host`，与桌面worker一起打包签名，按用户级登记安装路径；更新或移动后再次打开应用刷新路径。Windows仅HKCU，macOS仅用户NativeMessagingHosts目录。卸载命令保留其他安装拥有的记录；macOS拖废纸篓没有平台卸载回调，需要先用维护命令移除桥接登记或由下次安装修复。

收藏只在用户主动读取当前页并选中保存时发生。连接首次需桌面确认，范围限定到明确项目，保留回执与撤销入口；不分享桌面root令牌、模型密钥或供应商密钥。完整使用和内部隔离验收说明见 [browser-extension.md](browser-extension.md)。

## 授权服务配置材料

部署目录提供 `compose.yaml`、`nginx.conf.template`、`production.env.example` 以及桌面商业配置/标记模板。正式入口先检查域名、公证书SAN和期限、PostgreSQL、签名私钥类型与管理员哈希；缺真实配置会拒绝启动。

本轮未创建真实域名、证书或客户账号，也未运行公网部署。授权服务不接收客户商品素材、媒体、项目分析或模型密钥。主账号能力和24小时离线撤销成本见 [licensing.md](licensing.md)。

## 集中交付检查

最后一次集中检查应覆盖：实际安装包启动、浏览器首次连接及连续收藏、撤销/错误恢复、知识与证据回看、现有预算/资料范围约束，以及正式/内部配置标记的拒绝降级。Windows、真实商店安装、签名公证、跨设备与连续离线验证若未执行，分别保留 `NOT_RUN` / `NOT_VALIDATED`，不由契约或源码检查替代。


本机桥构建使用 scripts/build_native_host.py：仅引导编译时临时省去尚未生成的host侧车资源检查，生成真实二进制后再用完整Tauri配置打包，不用占位二进制通过检查。正式配置仍须真实域名、公钥/签名与商店ID；内部产物不能替代。
